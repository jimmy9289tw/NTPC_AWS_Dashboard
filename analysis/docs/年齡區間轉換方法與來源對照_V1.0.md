# 年齡區間轉換方法與來源對照 V1.0

## 1. 使用規則

本文件是 Word、CSV、儀表板、AWS AgentCore 與 Kiro 共用的年齡轉換契約。任何指標要呈現「18–35歲」，都必須在 `age-range-conversion-registry-v1.0.csv` 找到一筆登錄，並保留方法代號、輸入資料版本、公式、輸出值、證據類別與查核結果。

不能把「有一部分年齡重疊」誤寫成「已取得18–35」。特別是只有20–34總數時：

`Y(18–35) = Y(20–34) + Y(18) + Y(19) + Y(35)`

若來源沒有 `Y(18)`、`Y(19)`、`Y(35)`，就沒有唯一解。此時必須補單一年齡／微資料，或使用正式估計法並標成模型估計值；不能把未知值設成0，也不能把20–34直接改標18–35。

## 3. 共同公式

### 3.1 人數

`N(18–35)=Σ N(a), a=18,…,35`

來源若是15–19、20–24、25–29、30–34、35–39，只有20–34可直接納入；18、19與35必須另外取得或估計。

### 3.2 率與比例

`R(18–35)=Σ numerator(a) / Σ denominator(a)`

不得平均各組的率。失業率要合併失業人數與勞動力人口；教育占比要合併該教育程度人數與總人數。

### 3.3 平均數

`mean(18–35)=Σ n(g)·mean(g) / Σ n(g)`

每個 `g` 必須恰好位於18–35內，並有一致母體的人數／權數。僅有30–39平均薪資時，不能用人口比例切成30–35，因薪資與年齡不是均勻關係。

### 3.4 中位數與分位數

中位數不是線性統計量。不能平均各年齡組中位數，也不能由25–29與30–39兩個中位數推出18–35；必須取得個體微資料、權數或完整加權分布後重新計算。

## 5. 估計方法的最低查核門檻

1. 可加總性：估計單齡再合併回原始年齡組，必須重現原表總數。
2. 邊界回測：選擇有單齡真值的年份，先隱藏18、19、35，再比較估計值與真值。
3. 敏感度：PCLM平滑參數、IPF種子表或Sprague方法改變時，政策結論不能任意翻轉。
4. 調查設計：微資料須使用官方權數，並保留分層、群集與變異數估計方式。
5. 精確／估計分流：行政加總標「官方行政精確值」；抽樣加權標「官方調查估計值」；PCLM/IPF/Sprague標「模型估計值」。
6. 禁止規則：率不可平均、中位數不可平均、缺邊界不可改標、不同地理／年度／母體不可直接合併。

## 5.1 Sprague 的實際計算

Sprague 適用於連續、同口徑的5歲「人數」組。把相鄰5歲組總數寫成向量 `y`，依聯合國手冊的 Sprague 係數表建立矩陣 `S`，單一年齡估計為：

`x_hat = S y`

接著計算 `Y_hat(18–35)=Σ x_hat(a), a=18,…,35`。係數不可自行改寫，也不能套用在失業率、薪資中位數或開放式年齡區間。若結果出現負值、尖峰或合併回原5歲組不一致，停止使用並改採PCLM。

Sprague沒有內建標準誤。本案以已知單齡真值做遮蔽回測：在每個歷史年度或行政區，把單齡資料先合併成5歲組，再用Sprague拆回，計算 `r_h=log(Y_hat_h/Y_h)`。令 `q.025`、`q.975` 為回測log誤差分位數，真值的95%經驗預測區間寫成：

`[Y_hat·exp(−q.975), Y_hat·exp(−q.025)]`

同時報告bias、MAE、RMSE及負值率。這是「插值模型誤差」，不是官方抽樣誤差。

## 5.2 PCLM 的實際計算

PCLM把分組觀測 `y_g` 視為單齡期望數 `γ_a` 經組成矩陣 `C` 聚合後的結果：

`y_g ~ Poisson(μ_g)`

`μ = Cγ`

`log(γ) = Bθ`

其中 `B` 是單齡B-spline基底。參數以懲罰化概似估計：

`θ_hat = argmax { ℓ(y;θ) − (λ/2)||D^dθ||² }`

`λ` 控制平滑程度，必須用預先固定的交叉驗證／回測規則選擇並記錄，不能為了得到想要的答案手動調整。配適後得到非負單齡估計 `γ_hat`，再加總18–35。

不確定性以兩層呈現：第一層是有單齡真值的遮蔽回測，報bias、MAE、RMSE與經驗預測區間；第二層是重新抽取分組計數並重配模型的parametric bootstrap。若輸入為行政總數，bootstrap只代表模型敏感度，不可稱為行政資料的抽樣信賴區間。

## 5.3 IPF 的實際計算

IPF用於年齡×教育等交叉表，前提是已知可信的列、欄邊際及合理的非負種子表。以 `m_ij^(0)>0` 起始，反覆做：

`列縮放：m_ij^(t+1/2)=m_ij^t · r_i / Σ_j m_ij^t`

`欄縮放：m_ij^(t+1)=m_ij^(t+1/2) · c_j / Σ_i m_ij^(t+1/2)`

直到列、欄最大相對誤差小於預先設定的 `ε`。本案可先用PCLM產生年齡×教育單齡種子表，再用IPF使單齡人口符合MOI-POP1Y，教育分組總數符合MOI-EDU5Y。

IPF只會調整表格以符合邊際，不會憑空創造可識別資訊。其不確定性要用多組合理種子表、不同PCLM平滑參數及邊際版本做敏感度分析；若邊際來自抽樣調查，再以保留抽樣設計的bootstrap重抽邊際並重跑IPF。報告不同設定的結果範圍、邊際誤差與迭代次數，不能把「已收斂」當成「估計正確」。

## 5.4 20–34轉為18–35的執行順序

1. 若有18、19、35單齡資料，直接用AR-M1或AR-M2加入20–34，這是首選。
2. 若只有5歲人數組且有足夠相鄰組，人口總數可用Sprague或PCLM估計邊界；交叉分類表優先PCLM後再用IPF校準。
3. 若指標是率，先估／取得每個年齡的分子分母，再用AR-M5重算；不可直接插值率。
4. 若指標是平均薪資，需個體微資料或完全落在18–35內的組平均數及人數；30–39不能直接切成30–35。
5. 若指標是中位薪資，必須取得個體微資料或完整分布，三種拆齡法都不能從數個中位數恢復新的中位數。
6. 每次估計都輸出方法、參數、回測誤差與區間；沒有通過查核就維持「待補資料」，不進核心儀表板。

## 6. AWS、Kiro與儀表板執行規則

ETL每一列輸出必帶 `registry_id`。AWS Glue／Lambda依該ID選公式；S3保存原始、處理中、發布三層資料與雜湊；AgentCore回答時必須回傳來源、方法、精確／估計標記、點估計、區間與查核狀態。Kiro只生成或修改符合登錄表的方法程式，不得自行選擇未登錄的估算。儀表板遇到 `can_publish_18_35=否` 時顯示「資料不足／待人工查核」，不得填0或沿用25–29。
